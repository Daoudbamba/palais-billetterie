Démarrer la base:
docker compose -f infra/docker-compose.yml up -d

Arrêter/Nettoyer si besoin:
docker compose -f infra/docker-compose.yml down

Lancer le backend:
mvn -q -f backend/pom.xml spring-boot:run

Vérifier rapidement:
curl -sS http://localhost:8080/api/health
curl -sS http://localhost:8080/api/events


Si le port 8080 est occupé, arrêtez l’instance précédente:
pkill -f "spring-boot:run" || true

Analyse: Ce qui Manque pour un Backend Robuste & Innovant

Tests & Qualité
Unitaire et intégration (services, repositories, sécurité); tests d’API (MockMvc); contrats des webhooks Stripe.
Données de test, fixtures; couverture et CI (GitHub Actions).
Tests de performance (chargement dashboard/scan), tests E2E basiques.
Migrations & Données
Gestion de schéma avec Flyway/Liquibase au lieu de ddl-auto; migrations versionnées (index, colonnes, contraintes).
Seeds idempotents pour rôles, utilisateur admin, événements de démo.
Sécurité & Conformité
Gestion secrets via variables d’environnement (Stripe, JWT, scan.qrSecret) et @ConfigurationProperties.
RBAC par événement pour les contrôleurs (lier User.CONTROLLER aux eventId autorisés; valider côté ScanService).
Idempotency keys sur création de commandes/paiements; protection contre double traitement.
Hardening JWT: liste noire de refresh tokens révoqués, rotation stricte, détection d’usage anormal.
Validation stricte DTOs (tailles, formats, emails, téléphones), pagination sécurisée sur listes.
Journalisation d’accès et export audit (CSV/JSON) pour scan_logs et opérations sensibles.
Observabilité & Ops
Logs structurés (JSON), corrélation (traceId); métriques (Micrometer/Prometheus): latence scan, erreurs, taux d’acceptation.
Traces (OpenTelemetry); health probes étendus (DB, mail, Stripe).
Alerting basique (seuils erreurs, pics de rejets de scans).
Robustesse & Résilience
Circuit breakers/retry pour Stripe, SMTP; backoff exponentiel; file d’attente (ex: Redis/RabbitMQ) pour webhooks et mails.
Cache distribué (Redis) pour dashboard au lieu de mémoire locale; invalidation sur mutations.
Verrous ou check concurrents lors de use tickets pour éviter double scan simultané.
API & DX
Versionnement (/api/v1), documentation OpenAPI/Swagger; codes d’erreurs normalisés; limites de débit globales.
Uploads/imports CSV (contrôleurs, événements), exports (scans, ventes).
Feature flags (ex: activer QR signé par événement).
Données & Performance
Index additionnels: ticket(code) unique; contraintes FK; requêtes analytiques optimisées.
Pagination/tri sur listes; temps de réponse dashboard avec pré‑agrégations quotidiennes.
Produits Innovants
PWA contrôleur hors‑ligne avec synchronisation; passes Apple/Google Wallet; support NFC (optionnel).
Temps réel: WebSocket pour flux de scans live; tableau de bord dynamique.
Sécurité Produit
Politique mot de passe, brute‑force login; reCAPTCHA/anti‑bots sur endpoints publics sensibles.
RGPD: gestion consentements, suppression de compte, rétention de logs.
